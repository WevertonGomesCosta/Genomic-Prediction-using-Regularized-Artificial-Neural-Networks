# Output

This directory contains derived analytical objects, fitted-model results,
predictions, summaries, and publication-ready artifacts generated by the
project. Source data remain under [`data/`](../data/README.md).

The outputs connect the stages of the analytical workflow. Prepared data and
cross-validation designs provide common inputs to the genomic models. Saved
model results and held-out predictions support the comparison modules without
requiring another model fit.

## Simulated-data outputs

### Prepared data and cross-validation

| Module | Output directory (relative to `output/`) | Main file |
|:--|:--|:--|
| [M01](../analysis/simulated_data_audit.Rmd) | `simulated/audit/` | `preprocessed_simulated_common.rds` |
| [M02](../analysis/simulated_data_validation.Rmd) | `simulated/validation/` | `simulated_cv_design.rds` |

M01 prepares aligned phenotypes, true genetic values, marker genotypes, genetic
maps and scenario information. Its directory also contains scenario, QTL-map
and linkage-disequilibrium summaries.

M02 defines the common five repetitions of five outer folds and four nested
inner folds per outer-analysis set for ANN hyperparameter selection.
The assignment tables and design summary complement the saved partition object.

### Model comparison

[M05](../analysis/simulated_data_comparison.Rmd) reads the saved GBLUP and ANN
results and individual held-out predictions. It compares the seven procedures
separately within each of the six genetic scenarios.

The versioned file
[`simulated_model_scenario_summary.csv`](simulated/comparison/simulated_model_scenario_summary.csv)
under `simulated/comparison/` contains scenario-by-model means for Pearson,
Spearman, RMSE, MAE, prediction bias and calibration slope against each of the
two assessment targets: known true genetic values and simulated phenotypes.

The comparison does not pool the six scenarios into an overall model ranking.
The CSV export is documented in an optional chunk that is not executed during
routine rendering.

## Real-data outputs

### Phenotypic analysis

[R01](../analysis/real_data_phenotype.Rmd) stores its results under
`real/phenotype/`. These include descriptive field-data summaries,
mixed-model variance components, estimated individual BLUPs and execution
metadata. Genomic markers are not used in this phenotypic adjustment.

The main downstream input is `real_phenotype_blups.rds`, with a corresponding
CSV export. The BLUPs are derived from the phenotypic mixed model before
genomic cross-validation and are the response and assessment reference for
the subsequent genomic models.

### Genotype preparation and cross-validation

| Module | Output directory (relative to `output/`) | Main file |
|:--|:--|:--|
| [R02](../analysis/real_data_audit.Rmd) | `real/audit/` | `preprocessed_real_common.rds` |
| [R03](../analysis/real_data_validation.Rmd) | `real/validation/` | `real_cv_design.rds` |

R02 aligns the phenotypic BLUPs with the canonical genotype input
`geno_real.rds` and applies common marker quality control. The prepared
object contains the aligned 195 individuals, retained SNP panel and
prediction targets. Marker-quality, trait, family and individual-map
summaries are also produced.

R03 provides the common outer cross-validation partitions and nested inner
partitions for ANN hyperparameter selection, together with assignment
tables and a validation summary.

### Model comparison

[R05](../analysis/real_data_comparison.Rmd) reads the saved model outputs and
the shared cross-validation design; it does not refit either model family.
The seven versioned comparison CSVs under `real/comparison/` are:

| File | Content and unit of analysis |
|:--|:--|
| [`real_model_performance_summary.csv`](real/comparison/real_model_performance_summary.csv) | Split-level performance summaries by trait and model |
| [`real_model_common_split_correlation_summary.csv`](real/comparison/real_model_common_split_correlation_summary.csv) | Pearson and Spearman summaries on common finite splits by trait and model |
| [`real_model_predictive_winners.csv`](real/comparison/real_model_predictive_winners.csv) | Descriptive predictive leaders by trait and metric |
| [`real_ann_vs_gblup_matched_summary.csv`](real/comparison/real_ann_vs_gblup_matched_summary.csv) | Matched mean contrasts for each trait and ANN–GBLUP pair |
| [`real_model_ranking_summary.csv`](real/comparison/real_model_ranking_summary.csv) | Global Spearman, absolute rank errors and upper-group recovery by trait and model |
| [`real_model_ranking_winners.csv`](real/comparison/real_model_ranking_winners.csv) | Descriptive ranking leaders by trait and criterion, retaining tied optima |
| [`real_model_pairwise_quintile_weighted_kappa.csv`](real/comparison/real_model_pairwise_quintile_weighted_kappa.csv) | Weighted kappa, exact agreement and mean absolute quintile difference by trait and unordered model pair |

The units of evaluation differ across these results:

| Quantity | Count |
|:--|--:|
| Split-level evaluations (trait × model × outer split) | 525 |
| Individual held-out predictions | 20,475 |
| Individual ranking records (after averaging five OOF predictions) | 4,095 |
| Trait × ANN–GBLUP pair combinations | 36 |
| Mean contrasts across four primary metrics | 144 |
| Predicted quintile groups (trait × model × quintile) | 105 |
| Individuals per predicted quintile | 39 |
| Pairwise weighted kappa coefficients | 63 |

Split-level predictive association and individual ranking after OOF
aggregation are distinct quantities. The 12 ANN–GBLUP pairs per trait use
matched outer splits for the contrasts. Quintile agreement compares model
rankings, not predictions against observed BLUPs. Descriptive differences
and agreement do not establish statistical significance or predictive
superiority.

## Versioned and locally generated outputs

The repository preserves analytical source pages, the rendered website
and persisted scientific outputs, including the prepared data objects and
the comparison CSVs identified above. The file tables describe the
analytical products and their roles; they are not a claim that every
documented export is tracked in Git.

The repository [`.gitignore`](../.gitignore) excludes high-resolution
`*.tif` and `*.tiff` files, machine-local runtime artifacts under
`.local/` (including checkpoints, logs and temporary execution files),
and accidental interactive outputs under `analysis/output/`.
Locally retained historical scripts under `code/legacy/` are outside
the canonical workflow.

### Scope of the simulated comparison results

The canonical machine-readable M05 comparison summary is
[`simulated_model_scenario_summary.csv`](simulated/comparison/simulated_model_scenario_summary.csv).
The other five CSVs tracked in `simulated/comparison/` are not referenced by
the current M05 source:

- `simulated_ann_vs_gblup_paired_by_scenario.csv`;
- `simulated_ann_vs_gblup_paired_summary.csv`;
- `simulated_model_overall_summary.csv`;
- `simulated_model_pairwise_by_scenario.csv`;
- `simulated_model_pairwise_summary.csv`.

They are retained in the repository but do not constitute the canonical
comparison summaries for the current tutorial. In particular, the current
M05 does not rank models by pooling performance across C1–C6. All seven
R05 comparison CSVs listed above belong to the current real-data comparison.

### Reuse of persisted results

The versioned prepared datasets and validation designs support downstream
analyses without reconstructing the original inputs. In particular, M05
uses the four saved GBLUP and ANN result and prediction RDS objects listed
above. R05 uses the saved GBLUP and ANN results, predictions and individual
rankings together with the real validation design. Neither comparison
module requires a new model fit.

This intermediate reproduction route requires a compatible R environment
and the appropriate saved inputs. It is distinct from reconstructing
the complete workflow. Routine rendering is not a read-only operation:
some preparation and export blocks may write outputs. Use a separate
working copy if executing analysis code, and retain the original
versioned results for comparison.

The published tutorial can be inspected without new model fitting.
Computational reconstruction requires the relevant canonical inputs,
recorded software dependencies and deliberate execution of the documented
stages. See the [repository README](../README.md) and
[data documentation](../data/README.md) for these distinctions.
