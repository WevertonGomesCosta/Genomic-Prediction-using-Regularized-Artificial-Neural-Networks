# Output

This directory contains the versioned canonical scientific outputs required to
reproduce and render the public workflow without automatically repeating
computationally expensive model fitting.

Machine-local runtime artifacts such as logs, checkpoints, pilot results,
sensitivity analyses, convergence diagnostics, and other development artifacts
are stored outside the canonical output contract under the ignored `.local/`
directory.

## Layout

```text
output/
└── simulated/
    ├── audit/
    ├── validation/
    ├── gblup/
    ├── ann/
    │   ├── tuning/
    │   └── final/
    └── comparison/
```

A future real-data workflow should use `output/real/` and follow the same
dataset-first organization.

## Simulated-data audit and preprocessing

Files under `simulated/audit/`:

- `preprocessed_simulated_common.rds`
- `simulated_audit_summary.csv`
- `simulated_ld_summary.csv`
- `simulated_qtl_map.csv`
- `simulated_scenario_summary.csv`

These files document the validated simulated dataset and provide the canonical
preprocessed object consumed by downstream validation and modeling analyses.

## Frozen cross-validation design

Files under `simulated/validation/`:

- `simulated_cv_design.rds`
- `simulated_cv_design_audit.csv`
- `simulated_cv_design_summary.csv`
- `simulated_cv_inner_assignments.csv`
- `simulated_cv_outer_assignments.csv`

The same frozen outer partitions are used by GBLUP-ADE and all ANN variants.
This preserves direct paired comparison on the same outer-assessment
individuals.

## Canonical GBLUP-ADE

Files under `simulated/gblup/`:

- `simulated_gblup_ade_kernel_summary.csv`
- `simulated_gblup_ade_predictions.csv`
- `simulated_gblup_ade_predictions.rds`
- `simulated_gblup_ade_results.csv`
- `simulated_gblup_ade_results.rds`
- `simulated_gblup_ade_run_metadata.rds`

These files contain the canonical GBLUP-ADE diagnostics, predictions, results,

## Canonical ANN tuning

Files under `simulated/ann/tuning/`:

- `simulated_ann_tuning_manifest.csv`
- `simulated_ann_tuning_manifest.rds`
- `simulated_ann_tuning_fold_results.csv`
- `simulated_ann_tuning_fold_results.rds`
- `simulated_ann_tuning_candidate_summary.csv`
- `simulated_ann_tuning_candidate_summary.rds`
- `simulated_ann_tuning_selected_configurations.csv`
- `simulated_ann_tuning_selected_configurations.rds`
- `simulated_ann_tuning_run_metadata.rds`

The canonical tuning stage uses only outer-analysis data. Outer-assessment
individuals and true simulated genetic values are excluded from candidate
selection.

The canonical tuning ceiling remains 2000 epochs. Operational checkpoints used
during expensive fitting are local runtime artifacts and are not part of this
versioned output contract.

## Canonical final ANN

Files under `simulated/ann/final/`:

- `simulated_ann_epoch_selection.csv`
- `simulated_ann_epoch_selection.rds`
- `simulated_ann_predictions.csv`
- `simulated_ann_predictions.rds`
- `simulated_ann_results.csv`
- `simulated_ann_results.rds`
- `simulated_ann_run_metadata.rds`

The canonical final ANN protocol selects `Best_epoch` using only the
outer-analysis sample, reinitializes the network, refits on all outer-analysis
individuals for exactly that epoch count, and only then predicts the untouched
outer-assessment sample.

The final epoch-selection ceiling is 3000 epochs. This final-fit ceiling is
separate from the 2000-epoch canonical tuning ceiling.

## Canonical model comparison

Files under `simulated/comparison/`:

- `simulated_model_overall_summary.csv`
- `simulated_model_scenario_summary.csv`
- `simulated_ann_vs_gblup_paired_summary.csv`
- `simulated_ann_vs_gblup_paired_by_scenario.csv`

These four tables are generated by `code/simulated_model_comparison.R`.

The paired comparison uses identical `TaskID`, `SplitID`, and outer-assessment
individuals for GBLUP-ADE and all ANN variants.

## Canonical output contract

The simulated-data contract therefore contains 36 versioned scientific files:

- 5 audit/preprocessing files
- 5 validation-design files
- 6 GBLUP-ADE files
- 9 ANN tuning files
- 7 final ANN files
- 4 model-comparison files

Legacy development results, pilot outputs, sensitivity analyses, convergence
diagnostics, temporary model-fitting artifacts, operational checkpoints, and
execution logs are not part of the canonical scientific output contract.

## Local runtime artifacts

Machine-local artifacts are stored under the ignored `.local/` hierarchy,
including:

- `.local/logs/`
- `.local/checkpoints/`
- `.local/pilot/`

Routine website rendering reads the saved canonical artifacts under `output/`
and does not automatically rerun ANN tuning, final ANN fitting, or GBLUP
fitting.
