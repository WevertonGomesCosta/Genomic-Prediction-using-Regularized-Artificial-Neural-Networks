1. Purpose

This module closes the simulated-data workflow by comparing all seven genomic prediction methods on exactly the same outer-assessment individuals defined in M02:

  • GBLUP_A, GBLUP_AD, and GBLUP_ADE;
  • ANN_0, ANN_L1, ANN_L2, and ANN_L1_L2.

Predictive performance is evaluated using the known true simulated genetic value as the primary target. The observed phenotype is a complementary target because it includes residual variation.

Three principles define the comparison:

  • every method contributes the same 150 Scenario x outer split tasks;
  • every task contains the same 200 held-out individuals for all methods;
  • all 21 unordered method pairs are contrasted within the same outer splits. These paired summaries describe repeated cross-validation results and are not treated as tests based on 150 statistically independent replicates.

3. Evaluation metrics

The seven models are assessed using the same held-out performance measures. For individual \(i\), let \(p_i\) be the prediction, \(t_i\) the evaluation target, and \(n=200\) the size of each assessment set. True genetic value and observed phenotype are evaluated separately.

  • Pearson correlation measures linear association between prediction and target; larger values are better.
  • Spearman correlation measures monotonic rank association between prediction and target; larger values are better.
  • RMSE and MAE measure prediction error on the original target scale; smaller values are better.
  • Bias is mean(prediction - target) and is retained as a complementary calibration measure; values nearer zero are preferable.
  • Slope is the prediction coefficient in lm(target ~ prediction) and is retained as a complementary calibration measure; values nearer one are preferable.
  • No \(R^2\) metric is used.

The prediction errors and bias on the original target scale are \[ \mathrm{RMSE}=\sqrt{\frac{1}{n}\sum_{i=1}^{n}(p_i-t_i)^2},\qquad \mathrm{MAE}=\frac{1}{n}\sum_{i=1}^{n}|p_i-t_i|, \] \[ \mathrm{Bias}=\frac{1}{n}\sum_{i=1}^{n}(p_i-t_i). \] The calibration slope is the coefficient of the prediction in \(t_i=\alpha+\beta p_i+\varepsilon_i\). Pearson measures linear association, and Spearman measures rank association. Each metric is calculated within each outer-assessment task before the task-level values are averaged.

For the simulated benchmark, the known true genetic value is the primary evaluation target. Therefore the matched pairwise comparisons use exactly four primary genetic metrics: Pearson, Spearman, RMSE, and MAE. Phenotype metrics and bias and calibration slope are reported descriptively but are not included in the pairwise performance-contrast table.

6. Pairwise matched contrasts among all methods

All 21 unordered method pairs are evaluated within the same outer split. For Pearson and Spearman, performance advantage is \(M_1-M_2\); for RMSE and MAE it is \(M_2-M_1\), where the two values are the task-level metrics. Positive values favor Model_1 and negative values favor Model_2.

These calculations yield \(21\times4=84\) overall pairwise contrasts and \(6\times21\times4=504\) scenario-specific contrasts. Each overall contrast uses 150 matched tasks; each scenario contrast uses 25. Repeated cross-validation folds are not statistically independent replicates.

8. Scientific conclusion

Within the prespecified simulated-data benchmark, model performance is evaluated with four primary held-out metrics against the known true genetic value: Pearson correlation, Spearman correlation, RMSE, and MAE. Bias and calibration slope are complementary measures, and no \(R^2\) metric is used.

The seven methods are compared on the same frozen outer splits. All 21 unordered method pairs are evaluated within matched outer tasks, so no GBLUP or ANN method is privileged as the universal reference. The overall and scenario summaries describe the observed performance within the evaluated simulation conditions and prespecified model-search spaces; they do not establish a universal ranking between genomic mixed models and neural networks.

The four result summaries may also be exported for external inspection. Following the convention in M03/M04, this optional code is visible in the source file but disabled during the normal website build.
