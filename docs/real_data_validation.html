1. Purpose

This module defines the nested cross-validation procedure used by every genomic-prediction method fitted to the real Coffea arabica population. The partitions are created before model fitting and are reused unchanged by GBLUP-A, GBLUP-AD, GBLUP-ADE, and all ANN variants.

Cross-validation follows four specifications:

  • Repeated outer cross-validation: 5 repetitions of 5 outer folds provide 25 held-out evaluations.
  • Nested inner cross-validation: each outer analysis set is divided into 4 inner folds for ANN model selection.
  • Common partitions: the same outer and inner assignments are reused for Cer, BM, LP, GBLUP-A, GBLUP-AD, GBLUP-ADE, and all ANN configurations.
  • Information separation: BLUP values, genomic marker values, and model identity do not participate in fold generation.

Throughout this module, analysis set denotes individuals available for model development at the current validation level, whereas assessment set denotes individuals held out for evaluation at that level.

R03 receives the aligned real_common object prepared in R02 and creates the shared validation assignments used in the subsequent GBLUP and ANN modules. Its purpose is to define who is available for model development and who is held out for assessment, without fitting a genomic-prediction model.

The workflow proceeds from individual identifiers and fixed settings to repeated outer folds, the corresponding inner folds, checks of their coverage and separation, and a reusable validation object. The phenotypic targets are precomputed BLUPs from R01; the distinction between held-out individuals during genomic model assessment and earlier BLUP estimation is explained in Section 3.

4. Repeated outer cross-validation

Each of the five repetitions reshuffles the same 195 individuals. Within a repetition, the sampled ID sequence is divided into five disjoint folds of equal size. Since 195 / 5 = 39, one fold (39 individuals) is held out for assessment while the remaining four folds (156 individuals) form the analysis set used for model development.

4.1 Outer fold assignments

For repetition rep_id, set.seed(SEED_GLOBAL + rep_id) makes the shuffling reproducible and sample(ids, replace = FALSE) selects each individual exactly once. Assigning five consecutive blocks of 39 sampled IDs defines the five folds. Sorting the assignment table by ID afterward only makes the records easier to inspect: it does not change which fold each individual belongs to.

SplitID combines the repetition and fold numbers (for example, R01_F01). Each entry in outer_splits stores the corresponding analysis_ids and assessment_ids. This preserves the exact partition representation expected by both the GBLUP and ANN modules.

outer_assignment_list <- vector(
  "list",
  N_OUTER_REPEATS
)

outer_splits <- list()

for (rep_id in seq_len(N_OUTER_REPEATS)) {

  set.seed(
    SEED_GLOBAL + rep_id
  )

  shuffled_ids <- sample(
    ids,
    size = length(ids),
    replace = FALSE
  )

  assigned_folds <- rep(
    seq_len(N_OUTER_FOLDS),
    each = length(ids) / N_OUTER_FOLDS
  )

  assignment <- data.frame(
    Repetition = rep_id,
    ID = shuffled_ids,
    OuterFold = assigned_folds,
    stringsAsFactors = FALSE
  )

  assignment <- assignment[
    order(assignment$ID),
    ,
    drop = FALSE
  ]

  rownames(
    assignment
  ) <- NULL

  assignment$SplitID <- sprintf(
    "R%02d_F%02d",
    assignment$Repetition,
    assignment$OuterFold
  )

  outer_assignment_list[[rep_id]] <- assignment

  for (outer_fold in seq_len(N_OUTER_FOLDS)) {

    split_id <- sprintf(
      "R%02d_F%02d",
      rep_id,
      outer_fold
    )

    assessment_ids <- assignment$ID[
      assignment$OuterFold == outer_fold
    ]

    analysis_ids <- ids[
      !ids %in% assessment_ids
    ]

    outer_splits[[split_id]] <- list(
      split_id = split_id,
      repetition = rep_id,
      outer_fold = outer_fold,
      analysis_ids = analysis_ids,
      assessment_ids = assessment_ids
    )
  }
}

4.2 Outer split checks

The original checks inspect all 25 stored outer splits. For each split, Analysis_N counts individuals available for model development, Assessment_N counts those held out for prediction, and Overlap_N counts IDs appearing in both sets. A zero overlap confirms the separation of IDs within that split.

The additional outer_coverage check combines the five assessment folds of each repetition and verifies that every one of the 195 individual IDs appears exactly once. This is distinct from claiming that observations across different repetitions are independent: repetitions reshuffle the same population.

Meaning and scope of the outer cross-validation integrity checks
Property checked Scope Interpretation
Analysis and assessment sample sizes Each outer split 156 analysis IDs and 39 assessment IDs
Overlap_N == 0 Each outer split No individual belongs to both sets in that split
outer_coverage All five folds within each repetition All 195 IDs are assessed exactly once per repetition

These are checks of the partition assignments, not tests of predictive performance or of independence in the earlier BLUP estimation.

5. Nested inner cross-validation

5.1 Inner fold assignments

Each of the 25 outer splits has an outer analysis set of 156 individuals and a separate outer assessment set of 39 individuals. Inner validation uses only those 156 outer-analysis individuals; none of the 39 outer-assessment individuals can enter inner model selection.

For each outer split, the 156 IDs are shuffled and divided into four non-overlapping inner folds. One fold of 39 individuals serves as the inner assessment set, and the complementary 117 individuals form the inner analysis set. This yields four inner splits per outer split and 25 × 4 = 100 inner splits in total.

Sizes and roles of the nested analysis and assessment sets
Set Number of individuals Role
Outer analysis 156 Available for nested model development
Outer assessment 39 Held out from all inner folds
Inner analysis 117 Used to fit each candidate within the current inner split
Inner assessment 39 Used to compare candidates within the current inner split

The original seed formula, SEED_GLOBAL + 100000L + rep_id * 100L + outer_fold, sets a distinct deterministic shuffle for each outer split. Sampling draws only from outer_analysis_ids; subsequently sorting the assignment table by ID changes its display order, not its fold membership. Within each outer split, the four inner folds are labeled I1 to I4. The nested structure and its seed formula remain unchanged.

5.2 Inner split checks

The existing checks evaluate all 100 inner splits. Within a given outer split, each of the four inner assessment sets contains 39 IDs and each complementary inner analysis set contains 117 IDs. Their intersection must be empty. Across those four inner folds, inner_coverage verifies that all 156 outer-analysis IDs are assessed once.

A separate condition, recorded by outer_leakage, detects whether any of the 39 outer-assessment IDs appears in an inner analysis or assessment set. A value of FALSE for this flag is required: the inner folds must be subsets of the corresponding outer-analysis set.

6.2 Methodological scope of the validation

The same stored partitions apply to all traits and model variants because fold membership is generated without reference to the trait values, marker values or model identity. However, individual-level random assignment does not hold out complete progenies, years or environments. The design therefore addresses prediction of held-out individual BLUP targets within the represented coffee population, not leave-progeny-out, future-year or new-environment generalization.

There is also an important distinction between two information flows:

  • Genomic model fitting and tuning: the nested splits keep the outer-assessment IDs out of the inner folds, and the outer analysis and assessment IDs do not overlap within a split.
  • Phenotypic target estimation: the BLUP values were produced earlier in R01 using the available phenotypic records, rather than being re-estimated separately from each outer analysis set.

Consequently, the integrity checks support the stated separation during genomic modeling, but do not demonstrate complete independence of phenotypic target estimation. Predictive results should be described as assessments against precomputed BLUPs, with this limitation stated alongside their interpretation.

9. Synthesis and transition to genomic prediction

R03 provides the fixed and common nested cross-validation design for the real Coffea arabica population. It defines which individuals enter model development, inner model selection, and held-out assessment; it does not fit GBLUP or ANN models.

  • Population: 195 aligned plants with the previously estimated Cer, BM, and LP BLUP targets and the common SNP panel from R02.
  • Outer assessment: five repetitions of five folds, giving 25 splits, each with 156 analysis individuals and 39 held-out assessment individuals.
  • Inner model selection: four folds within each outer analysis set, giving 100 inner splits, each with 117 analysis and 39 assessment individuals.
  • Integrity: the original checks confirm coverage and absence of overlap within splits, including exclusion of outer-assessment IDs from every corresponding inner split.
  • Reproducibility: fixed seeds, original SplitID labels and stored cv_design fields are reused by the downstream genomic-prediction modules.

Each plant is assessed once per outer repetition. The repeated partitions are not independent biological populations, and fold membership is not generated from BLUP values, marker values, progeny or model identity. In particular, the assessment is against BLUPs estimated before partitioning, not against phenotypes whose estimation excluded the held-out individuals (Sections 3 and 6).

The next modules use the unchanged real_cv_design.rds to fit and compare GBLUP-A, GBLUP-AD, GBLUP-ADE, and the regularized ANN variants on matching held-out partitions.
