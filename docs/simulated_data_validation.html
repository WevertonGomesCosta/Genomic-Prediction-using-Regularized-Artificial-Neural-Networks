1. Purpose

This module establishes common outer cross-validation partitions for GBLUP-A, GBLUP-AD, GBLUP-ADE, and all ANN variants. Nested inner cross-validation is used for ANN hyperparameter selection. The partitions are created before model fitting so every method is evaluated using the same outer assessment individuals.

Cross-validation follows four specifications:

  • Repeated outer cross-validation: 5 repetitions of 5 outer folds produce 25 outer held-out evaluations.
  • Nested inner cross-validation: each outer analysis set is divided into 4 inner folds for ANN hyperparameter selection.
  • Common partitions: the outer assessment partitions are shared by GBLUP and ANN across all six simulation scenarios. Inner partitions are reused to compare ANN candidates within each outer split.
  • Information separation: phenotype, true genetic value, scenario, and model identity do not participate in fold generation.

Two terms are used throughout the module:

  • Analysis set: individuals available for model development at the current validation level.
  • Assessment set: individuals held out from that development step and used only for evaluation at the same level.

The distinction is especially important in nested validation. The outer assessment individuals remain untouched until final prediction, whereas the inner assessment individuals are used only to compare ANN candidates inside the corresponding outer analysis set.

4. Repeated outer cross-validation

The outer level provides the final held-out evaluation. In each repetition, the 1,000 row identifiers are shuffled reproducibly and assigned cyclically to five fold labels. Because 1,000 is divisible by five, every fold contains exactly 200 individuals.

For a given fold:

  • the 200 individuals assigned to that fold form the outer assessment set;
  • the remaining 800 individuals form the outer analysis set;
  • the two sets are disjoint and together recover all 1,000 individuals.

4.1 Outer fold assignments

The code below repeats the same direct assignment procedure five times. The seed changes with the repetition number, which gives each repetition a distinct assignment while preserving exact reproducibility.

outer_assignment_list <- vector("list", N_OUTER_REPEATS)

The outer-assignment list is initialized once. The next block shuffles the same 1,000 identifiers independently for each repetition and assigns them to five balanced folds.

# Build one balanced five-fold assignment for each repetition.
for (rep_id in seq_len(N_OUTER_REPEATS)) {

  set.seed(SEED_GLOBAL + rep_id)

  shuffled_ids <- sample(ids, size = length(ids), replace = FALSE)

  assigned_folds <- rep(seq_len(N_OUTER_FOLDS), length.out = length(ids))

  assignment <- data.frame(ID = shuffled_ids, Fold = assigned_folds, stringsAsFactors = FALSE)

  # Sort only the displayed/stored rows; fold membership is already fixed.
  assignment <- assignment[order(assignment$ID),, drop = FALSE]
  rownames(assignment) <- NULL

  outer_assignment_list[[rep_id]] <- data.frame(
    Repetition = rep_id,
    ID = assignment$ID,
    OuterFold = assignment$Fold,
    stringsAsFactors = FALSE
  )
}

5. Nested inner cross-validation

The inner level is created inside each outer analysis set. It is used for ANN hyperparameter selection and therefore cannot contain any of the 200 outer assessment individuals.

For each 800-individual outer analysis set:

  • the IDs are shuffled with a seed determined by the outer repetition and fold;
  • four balanced inner folds of 200 individuals are created;
  • one inner fold becomes the inner assessment set;
  • the other 600 individuals become the inner analysis set;
  • ANN early validation is drawn later only from the current inner analysis data, not from the inner assessment or outer assessment sets.

5.1 Inner fold assignments

The code repeats this procedure for all 25 outer splits, producing 100 inner splits in total. The outer assessment IDs never enter the inner assignment operation because the starting vector is always outer_split$analysis_ids.

inner_assignments_list <- vector("list", length(outer_splits))
names(inner_assignments_list) <- names(outer_splits)

inner_splits <- setNames(vector("list", length(outer_splits)), names(outer_splits))

The nested data structures are initialized. The inner-fold loop begins only with outer_split$analysis_ids, ensuring that the 200 outer-assessment individuals cannot enter inner tuning.

# Generate four inner folds separately within each outer analysis set.
for (split_id in names(outer_splits)) {

  outer_split <- outer_splits[[split_id]]

  split_tokens <- strsplit(
    sub("^R", "", split_id),
    "_F"
  )[[1]]

  rep_id <- as.integer(split_tokens[1])
  outer_fold <- as.integer(split_tokens[2])

  inner_seed <- SEED_GLOBAL + 100000L + rep_id * 100L + outer_fold

  set.seed(inner_seed)

  shuffled_ids <- sample(outer_split$analysis_ids, size = length(outer_split$analysis_ids), replace = FALSE)

  assigned_folds <- rep(seq_len(N_INNER_FOLDS), length.out = length(outer_split$analysis_ids))

  assignment <- data.frame(ID = shuffled_ids, Fold = assigned_folds, stringsAsFactors = FALSE)

  assignment <- assignment[order(assignment$ID),, drop = FALSE]
  rownames(assignment) <- NULL

  inner_assignments_list[[split_id]] <- data.frame(
    SplitID = split_id,
    Repetition = rep_id,
    OuterFold = outer_fold,
    ID = assignment$ID,
    InnerFold = assignment$Fold,
    stringsAsFactors = FALSE
  )

  current_inner_splits <- setNames(vector("list", N_INNER_FOLDS), paste0("I", seq_len(N_INNER_FOLDS)))

  # Convert every inner fold into explicit analysis and assessment ID sets.
  for (inner_fold in seq_len(N_INNER_FOLDS)) {

    inner_assessment_ids <- assignment$ID[assignment$Fold == inner_fold]

    inner_analysis_ids <- setdiff(outer_split$analysis_ids, inner_assessment_ids)

    current_inner_splits[[paste0("I", inner_fold)]] <- list(
      split_id = split_id,
      inner_fold = inner_fold,
      analysis_ids = sort(inner_analysis_ids),
      assessment_ids = sort(inner_assessment_ids)
    )
  }

  inner_splits[[split_id]] <- current_inner_splits
}

  • True genetic value not used: known simulated genetic values are reserved for held-out evaluation and never determine partitions or ANN tuning.
