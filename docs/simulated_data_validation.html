Purpose

This analysis freezes the validation design used by all genomic prediction models fitted to the simulated dataset.

The design is created before model fitting and is independent of phenotype, true genetic value, scenario, and model. Consequently, GBLUP-ADE and all ANN variants are evaluated on exactly the same outer assessment individuals.

The canonical design uses:

  • 5 outer folds;
  • 5 outer repetitions;
  • 4 inner folds within each outer analysis set;
  • deterministic seeds derived from the project-wide seed;
  • the same outer and inner partitions for all six simulation scenarios.

The outer assessment sets are reserved exclusively for final model evaluation. The inner folds are reserved for ANN hyperparameter tuning. True simulated genetic values are never used to generate partitions or tune models.

How to read the validation design

The validation scheme separates model development from final predictive evaluation. An analysis set contains the individuals available for fitting or tuning, whereas the corresponding assessment set remains held out for evaluation at that level of cross-validation. Outer assessment individuals are therefore never used to choose ANN hyperparameters or training duration.

Internal integrity checks still verify file availability, ID alignment, partition sizes, disjointness, and coverage. Those checks remain executable and are exported with the validation outputs, but the public page emphasizes the validation logic that determines how models are trained and evaluated.

Canonical data prerequisite

The validation design is built only after the simulated-data audit has completed without any blocking check.

Individual universe

Partitions are generated from the 1,000 canonical row identifiers only. No phenotype, true genetic value, scenario label, or model information is used to define the partitions. Alignment with the canonical phenotype, true-genetic- value, and genotype matrices is verified internally before the folds are built.

Outer repeated cross-validation

For each repetition, sample() randomly permutes the 1,000 canonical individual IDs using a deterministic seed. rep() then assigns the shuffled IDs across five fold labels as evenly as possible. Because 1,000 is exactly divisible by five, every outer assessment fold contains 200 individuals and the remaining 800 form its outer analysis set.

The same procedure is repeated five times with different deterministic seeds, producing 25 outer train–test comparisons while preserving exact reproducibility.

outer_assignments <- do.call(
  rbind,
  lapply(
    seq_len(N_OUTER_REPEATS),
    function(rep_id) {
      assignment <- balanced_fold_assignment(
        ids = ids,
        k = N_OUTER_FOLDS,
        seed = SEED_GLOBAL + rep_id
      )

      data.frame(
        Repetition = rep_id,
        ID = assignment$ID,
        OuterFold = assignment$Fold,
        stringsAsFactors = FALSE
      )
    }
  )
)

Explicit outer split objects

The assignment table is then converted into explicit analysis and assessment ID sets for each outer split. For a given split, setdiff() removes the 200 assessment IDs from the 1,000-individual universe, leaving the corresponding 800-individual analysis set. This representation is the object consumed by the modeling modules.

outer_split_ids <- unique(
  outer_assignments$SplitID
)

outer_split_ids <- outer_split_ids[
  order(outer_split_ids)
]

outer_splits <- setNames(
  vector("list", length(outer_split_ids)),
  outer_split_ids
)

for (split_id in outer_split_ids) {
  assessment_ids <- outer_assignments$ID[
    outer_assignments$SplitID == split_id
  ]

  analysis_ids <- setdiff(
    ids,
    assessment_ids
  )

  outer_splits[[split_id]] <- list(
    split_id = split_id,
    analysis_ids = sort(analysis_ids),
    assessment_ids = sort(assessment_ids)
  )
}

outer_split_integrity <- all(
  vapply(
    outer_splits,
    function(x) {
      length(x$analysis_ids) == 800L &&
        length(x$assessment_ids) == 200L &&
        length(intersect(
          x$analysis_ids,
          x$assessment_ids

        identical(
          sort(c(
            x$analysis_ids,

Nested inner folds

Each outer analysis set is partitioned again for ANN hyperparameter selection. Within a given outer split, one inner fold acts as the assessment subset and the remaining inner individuals form the analysis subset. The operation setdiff() constructs the analysis IDs by removing the current assessment IDs, which makes the two sets disjoint by construction.

With 800 individuals in each outer analysis set and four inner folds, every inner assessment set contains 200 individuals and every inner analysis set contains 600.

Scenario and model independence

The split object contains no scenario, phenotype, true genetic value, or model information. The same partitions are therefore reused for C1-C6 and for every prediction method. This independence is verified internally from the fields stored in the frozen split objects.

Validation contract

The frozen validation protocol is:

  1. For each of the 5 repetitions, every individual belongs to exactly one of the 5 outer assessment folds.
  2. The same 25 outer splits are used for C1-C6 and for GBLUP-ADE, ANN-0, ANN-L1, ANN-L2, and ANN-L1+L2.
  3. Outer assessment phenotypes and true genetic values are not used for model fitting or hyperparameter tuning.
  4. ANN hyperparameters are selected using the 4 inner folds defined within the corresponding outer analysis set.
  5. Early stopping, if used during inner ANN fitting, must use data drawn only from the current inner analysis set. The inner assessment set must remain reserved for candidate evaluation.
  6. After ANN hyperparameters are selected, the final outer model must be fitted using only the outer analysis individuals. The outer assessment individuals remain untouched until final prediction.
  7. Simulated true genetic values are never used to tune ANN architecture, learning rate, L1, L2, epoch count, or any other model choice.
  8. Primary simulated-data evaluation compares final predictions with the true genetic value only after the model for that outer split has been frozen.
  9. Secondary phenotype-prediction metrics may be computed on the same outer assessment individuals, but cannot feed back into model selection.

Internal validation status

The detailed integrity checklist is evaluated before the frozen design is written, but it is retained as a validation artifact rather than reproduced as a reader-facing table.

The internal checks classify the frozen validation design as PASS. A blocking condition would prevent creation of the canonical cross-validation object.

Frozen validation object

The validated design is stored only after all blocking conditions have been excluded. The saved object contains the outer and inner assignments together with their explicit analysis/assessment ID sets and is the single validation contract consumed by GBLUP-ADE and ANN.

The detailed assignment tables and validation audit remain available as versioned outputs for reproducibility and maintenance, while the modeling modules consume simulated_cv_design.rds directly.
