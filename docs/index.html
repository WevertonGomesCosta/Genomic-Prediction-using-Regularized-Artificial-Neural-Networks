Project overview

This reproducible research project evaluates regularized artificial neural networks for genomic prediction, using simulated genomic data and a real Coffea arabica dataset.

The central comparison is between a genomic mixed model and four neural-network variants fitted under the same validation design:

  • GBLUP-ADE: additive, dominance, and epistatic genomic effects;
  • ANN-0: neural network without L1/L2 weight penalties;
  • ANN-L1: neural network with L1 weight regularization;
  • ANN-L2: neural network with L2 weight regularization;
  • ANN-L1+L2: neural network with simultaneous L1 and L2 weight penalties.

The project is organized with workflowr, so the analysis pages, source code, results, and generated website remain linked to a reproducible computational workflow.

Scientific questions

The simulated-data branch evaluates how predictive performance changes across a gradient of genetic architectures. The real-data branch will apply the same model-comparison logic to coffee production and fruit-quality phenotypes after auditing genotype and phenotype provenance.

The primary simulated-data outcome is prediction of the true simulated genetic value. Phenotype prediction is retained as a secondary outcome.

Validation principles

The analysis follows a common validation contract:

  1. the same outer partitions are used by all competing models;
  2. ANN hyperparameter tuning is restricted to the outer-analysis sample;
  3. outer-assessment individuals are not used for hyperparameter selection;
  4. preprocessing parameters are estimated from training data only;
  5. true simulated genetic values are excluded from model fitting and tuning;
  6. predictive correlation, RMSE, MAE, bias, slope, and \(R^2\) are reported under the same held-out design.

Simulated-data workflow

The canonical simulated-data analysis is organized into five public modules:

  1. Data audit — verifies data integrity, provenance, genotype and phenotype structure, simulation metadata, QTL information, and scenario properties.
  2. Validation design — freezes the common outer and inner cross-validation design used by all competing models.
  3. Parallel modeling branches:
    • GBLUP-ADE
    • Regularized ANN
  4. Model comparison — verifies direct comparability and summarizes GBLUP-ADE versus ANN performance after both modeling branches are complete.

ANN hyperparameter tuning is an internal stage of the ANN workflow rather than a separate public analysis page. Development sensitivity, boundary, and convergence diagnostics were used to establish and validate the final ANN protocol; their methodological conclusions are incorporated into the canonical ANN analysis and they are no longer part of the public workflow.

Within the prespecified canonical model and architecture search space, GBLUP-ADE showed the strongest overall predictive performance in the canonical simulated-data analysis, while ANN-L1 and ANN-L1+L2 were the best-performing neural-network variants.

Real-data workflow

The real coffee-data branch will use the same separation between data audit, validation, model fitting, and comparison. Phenotype correction and genotype provenance will be audited before predictive modelling.

Reproducibility

The repository contains the workflowr source pages under analysis/, generated site pages under docs/, input data under data/, and reproducible derived objects and results under output/.

Computationally intensive ANN fitting is separated from routine site rendering. A normal website build reads saved canonical outputs and does not repeat the expensive tuning or final ANN fits. The execution contract is documented in the repository README and in the canonical ANN analysis.
